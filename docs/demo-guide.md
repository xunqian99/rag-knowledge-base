# 演示流程

按以下顺序演示，可覆盖系统全部核心能力，耗时约 3 分钟。

| # | 操作 | 展示的能力 |
|---|---|---|
| 1 | `docker compose up -d` | 一条命令拉起中间件与应用 |
| 2 | 访问 `GET /api/system/health` | 五项依赖（PostgreSQL / Redis / Elasticsearch / 千帆 Key / 硅基流动 Key）自检 |
| 3 | 上传一份 PDF | 自动解析、按标题层级切分、向量化并建立索引 |
| 4 | 提问一个文档中确有答案的问题 | SSE 逐字输出、答案下方的引用来源 |
| 5 | 提问一个文档中没有的问题 | 如实回答"资料中没有找到相关内容"，不编造 |
| 6 | 重复提问步骤 4 的问题 | 缓存命中，耗时由 4.5s 降至 0.02s |
| 7 | 删除步骤 3 上传的文档后再次提问 | 缓存正确失效，答案不再引用已删除内容 |

## 补充说明

- 步骤 5 与步骤 7 容易在演示中被忽略，但它们分别验证了防幻觉与
  缓存失效这两条正确性前提。
- 若要演示降级路径，需先修改配置或停止对应容器，
  并且使用一个此前未提过的新问题 —— 提问旧问题会命中缓存，
  实际验证的是缓存逻辑而非降级逻辑。

## 调试接口

观察同一问题在检索各阶段的名次变化，可依次调用四个调试接口：

```bash
curl "http://localhost:8080/api/search/bm25?q=出差住宿能报多少"      # 仅 BM25 召回
curl "http://localhost:8080/api/search/hybrid?q=出差住宿能报多少"     # 双路召回原始结果
curl "http://localhost:8080/api/search/fused?q=出差住宿能报多少"      # RRF 融合后
curl "http://localhost:8080/api/search/reranked?q=出差住宿能报多少"   # 完整链路
```
